# 给 ZCode：voyage 第四轮修改指令（性能 + 连贯性 + 教育学约束）

用户要求：① 按小穗审查结果改；② 算法高效，响应 <10ms；③ 功能设计要符合心理学与教育学。

---

## 一、性能基线（我刚实测，服务在跑）

| 端点 | 实测 |
|---|---|
| `/api/state` | 1.32 ms |
| `/api/graph` | 0.88 ms |
| `/api/opportunities` | 0.81 ms |
| `/`（HTML 143KB） | 1.39 ms |

**结论：现在已经远低于 10ms，别做无意义的优化。** 真正要做的是「别让它以后变慢」。

### 性能护栏（必须做，防止以后劣化）
1. **序列化结果缓存**：state 变更时置 dirty，只在 dirty 时重新 `json.Marshal`，请求直接写缓存字节；同时发 `ETag`，客户端带 `If-None-Match` 就回 304。
2. **状态分片**：`progress.json` / `tutor.json` / `stats.json` / `works.json`，`/api/state` 只返回前端首屏需要的字段（今天三步、进度、连签、时间预算），其余按需拉。
3. **禁止在 handler 里做 IO**：所有磁盘读写走 store 层，且只在 dirty 时落盘。
4. **加基准测试**：`BenchmarkStateAPI`、`BenchmarkGraphAPI`，CI 里跑，超过 10ms 直接 fail（用 benchstat 或阈值断言）。
5. 会话懒加载：`/api/session?id=`，state 里只放元信息（之前提过，这次一并做）。

## 二、功能连贯性 P0（三件，优先于架构重构）

### P0-1 复习并入今日三步
- `todaySteps()` 现在是 讲 / 练 / 副本，fsrs 到期卡片在闭环外
- 改成：有到期卡片时，第一屏出现第 0 步「复习 N 张（约 M 分钟）」，做完才算今天完成
- 验收：造 3 张到期卡，首页必须出现复习步，且做完后消失

### P0-2 时间预算真的减步
- 现状：`if((mood==='10'||mood==='30')&&...) steps[2].light=true` —— 只改样式
- 改成：`10` → 只渲染第 1 步 + 一道题，第 2/3 步折叠并显示「今天到此为止，明天继续」；`30` → 保留 1+2 步
- 后端同样：TimeBudget=10 时，`/api/state` 不下发 exercises 与 dungeons
- 验收：选 10 分钟后刷新，页面只有一步

### P0-3 关联图诚实化
- 图例承诺「练习中真实调用的连接（×N=次数）」，但后端只发 `sequence` / `context` 边
- 二选一：
  - A. 补 usage 边：从 `sessions[].messages` 与 `exercises` 统计「同一节课里共同被引用的知识点」，输出 `{from,to,type:"usage",weight:N}`
  - B. 改图例：删掉 usage 那句，只留「课程先后」
- 推荐 A（这是产品的差异化卖点），但要在图例里写清数据来源
- 验收：完成两节共享知识点的课，图上出现一条 usage 边且权重 ≥2

## 三、教育心理学约束（写进 teachSystem，并转成验收点）

这部分不是装饰，每一条都要能在界面上验证。

### 1. 认知负荷（Sweller）
- 一次只给一个动作；讲解分块，单块 ≤5 行
- 先给样例（worked example），再让用户自己做（样例效应）
- 验收：10 分钟档开场 ≤3 句 + 1 题

### 2. 检索练习（Roediger & Karpicke）
- 讲解后立刻一题，不要「先讲完一整章再测」
- 判断题用「把输出贴上来」，不用「请解释原理」
- 验收：每节课至少有 1 次检索，而非纯讲解

### 3. 间隔重复（已有 FSRS）
- 到期卡片必须出现在今日闭环（见 P0-1）
- 复习题优先取「曾经错过的」（wrongHits）
- 验收：错题在 24h/72h 各被重出一次

### 4. 最近发展区 ZPD（Vygotsky）
- 难度自适应只保留一套（FSRS + 固定难度档），Elo/bandit 默认关
- 目标正确率区间 60%～80%：低于 50% 降档，高于 90% 升档
- 验收：进度页显示「当前档位」与「近 10 题正确率」

### 5. 自我决定理论（Deci & Ryan：自主 / 胜任 / 归属）
- 自主：每节课开场给两个选择（「练概念」/「直接做」），保留掌控感
- 胜任：每次判定给出「你比上次快/少错」的具体对比，不空夸
- 归属：完成副本后显示「这条路有 N 个人走过」（本地统计即可，不做社交）
- 验收：三个需求各自在界面上有可见位置

### 6. 心流（Csikszentmihalyi）
- 单步时长控制在 3～8 分钟；超过 10 分钟自动拆步
- 验收：每步有预估时长，且实际时长记录进 stats

### 7. 启动成本（Fogg：B=MAP）
- 首页只留一个按钮（已有），并把「上次你卡在 X」放在最上面（已有）
- 加「两分钟版」：任何一步都能点「我只做两分钟」，进去只做一道最小题
- 验收：点两分钟能在一分钟内进入可操作状态

### 8. 反馈与归因（Dweck 成长型思维）
- 判错时讲「差在哪一步」，不讲「你不擅长这个」
- 不出现「天赋/聪明」类评价词
- 验收：错误文案里必须包含「具体差在哪」的一句话

### 9. 防习得性无助
- 连续 2 次同类型出错 → 自动降档并给一个更小的同类题
- 验收：连错两次后难度档位下降

## 四、架构 P1（P0 之后再动）

1. 把 `save/load/stateMutex` 从 Server 抽到 `internal/store`
2. 抽三个接口：`LLMClient`、`Fetcher`、`Clock`（有 Clock 才能不睡时间测 fsrs）
3. 自迭代隔离：在 `git worktree` 或 clone 里跑，产物是 patch，人工确认后合并；涉及 `outpost2-data/` 或 schema 变更的一律不自动提交
