# 第八轮：把「第一次看它的人」会踩的坑先踩掉

来源：2026-10-28 21:18 主人要求「客观点，就当第一次发现这个项目的 AI」。下面五条按「会不会毁掉教学闭环」排序，每条都给可验证的验收标准。

---

## P0-1 收尾判定不能只靠 `[PASS]` 魔法标记

**问题**：判定完全依赖模型在回复里吐 `[PASS]` / `[PASS:partial]` / `[FU-PASS]`。模型换了版本、少吐一个括号、或者把标记包在代码块里，闭环静默断开，没有任何报警。今天实测六轮才等到一个 `[PASS]`，中途全靠模型自觉。

**要做**：
1. 判定器双通道：优先解析标记；标记缺失时，走「结构化判定」——把最近一轮学生回答 + 验收标准丢给一次单独的小调用，要求输出 `{pass: bool, reason, cause}`，同样落库。
2. 标记解析容错：允许全角括号、`【PASS】`、行内出现、前后有空格、出现在代码块里（视为误写，记 warning 不判过）。
3. 每节课结束写一条 `diagnostics` 记录：本轮判定来自哪个通道、耗时、是否二次校验。

**验收**：
- 造一个「模型永不吐 [PASS]」的假客户端，跑完一整节课，仍能正常收尾（走结构化通道），且 `diagnostics.channel = "structured"`。
- 造一个「吐在代码块里」的假客户端，不得判过。
- 造一个「吐 `【PASS】` 全角」的，正常判过。

## P0-2 「记住你错在哪」必须真的参与教学，而不是只落库

**问题**：`wrongReasons` / `wrongNotes` 记了，但开花环节没有真正使用——开场引用、引导档位、追问方式都没读它。今天实测出的四个 bug 全是这一环的。

**要做**：
1. 开场时检索该科目最近 3 条 `wrongReasons`，若与本节知识点相关，开场必须点名一条（自然句，不许生硬套模板）。
2. 引导档位初始值由历史决定：同一知识点连续错 2 次以上，直接从 `GuideHint` 起步，不再给 `GuideSample`。
3. 收尾「下节预告」里，如果本节有未消除的错因，必须写一句「下次会先考你这个」。

**验收**：
- 预置一条「同一知识点 slip×2」的历史，开课时 `guideLevels` 初始值必须是 2（hint），不是 1（sample）。
- 预置一条相关错因，开场文本里必须出现该错因的自然表述（用关键词断言，不比对整句）。
- 无历史时，开场不得出现任何「上次你…」类句子。

## P1-1 文案要给孩子看，不是给工程师看

**问题**：界面上「引导：样例」「档位」「判定」这些词是工程词。目标用户是没人带的孩子。

**要做**：建一张文案映射表（`internal/server/static/copy.json`），把所有面向用户的工程词换成白话，代码里只引用 key：
- `guide.sample` → 「我先给你看个例子」
- `guide.hint` → 「我提示你一点」
- `guide.ask` → 「你先说说看」
- `verdict.partial` → 「半懂也记下了，再答一次就过」
- `level` → 「我讲得多细」

**验收**：`grep -r "引导：\|档位\|判定" internal/server/static/index.html` 在呈现给用户的字符串里为 0 命中（注释与变量名不算）；映射表有单测覆盖「每个 key 都有值」。

## P1-2 server 上帝对象要拆，且要有测试

**问题**：`internal/server/server.go` 约 2700 行、49 个 handler、32 个字段。llm 93.5%、tutor 85%，这块没提。

**要做**（先止血，不重写）：
1. 按域拆文件：`handlers_learn.go`（tutor/exercise/verdict）、`handlers_kb.go`（notes/reflib/kb）、`handlers_shop.go`（fetch/opportunities/iterate）、`handlers_sys.go`（state/config/version/export）。只移动，不改逻辑，每拆一组一个 commit。
2. 给 `/api/state`、`/api/tutor/send`、`/api/exercise/answer` 三条主链路补 handler 级测试（httptest），覆盖成功 + 参数错误 + 状态冲突。

**验收**：`server.go` 降到 800 行以下；`go test ./internal/server` 覆盖率 ≥ 50%；三条主链路各有 ≥3 个用例；拆分前后 `go test ./...` 全绿且接口零变更（用同一份 curl 快照比对响应结构）。

## P1-3 命名收敛（今天已经咬过人）

**问题**：outpost2 / voyage / 前哨2.0 / 前哨 / VOYAGE 五种写法并存。今天「启动前哨.cmd 找 outpost2.exe」就是这么坏的。

**要做**：
1. 全仓扫描，列出所有残留字符串（二进制名、目录名、README 标题、脚本、日志前缀、数据目录）。
2. 数据目录 `outpost2-data/` 保留不动（动了要迁移），但在代码里统一常量引用，并加注释说明「历史名，勿改」。
3. 其余全部收敛到 `voyage`；用户可见名称统一「Voyage · 前哨」。
4. 加一条 CI 检查：除白名单外，源码里出现 `outpost2` 字面量即失败。

**验收**：`grep -rn "outpost2" --include=*.go --include=*.md --include=*.cmd .` 只剩数据目录常量与迁移说明；CI 新检查在故意插入一处 `outpost2` 时报红。

## P2-1 产品定位与真实用户路径

**问题**：它最缺的不是功能，是「有人真的用它学完一件事」。今天我做第一个学生，一节课揪出四个 bug。

**要做**：
1. 建 `docs/user-journeys/` 目录，用文字逐屏记录「一个零基础学生从打开到交作品的完整路径」，每屏标出他自己的原话（不是我们的文案）。
2. 每轮迭代结束，必须有一次真实走查（我或 ZCode 扮演学生），把「卡住的地方」记进 `docs/ui-review/走查N.md`。

**验收**：`docs/user-journeys/` 至少 1 份完整路径；走查记录至少 1 份；里面必须包含 ≥3 条真实困难（不许写「体验良好」）。
