## 一、先清数据（他要求的）

用户说「把那些数据删了」——指他刚才点击产生/留下的副本与学习进度数据。

要求：
1. **先备份**：把 `outpost2-data/state.json` 复制成 `state.json.bak-YYYYMMDD-HHMM`，再动手。
2. 清空这些运行时数据：副本（dungeons）、纪念卡/收藏墙（trophies）、进度与连签（Done/Stats/Ledger 里的进度计数）、lastStop。
3. **保留**：课程/知识点（lessons/curriculum）、LLM 配置（llm.json）、阅读材料（readings.json）、笔记。
4. 清完重启服务一次，确认首页回到「没有进行中的课」的干净状态，并留一张截图。

## 二、核心改造：助教必须先给「动作」，再给「内容」

现状问题：开场一口气给概念、目标、材料、检查题，但没有一个明确的「现在动手做什么」。

### 2.1 开场固定四段（模板硬约束，写进 teachSystem）
```
【今天做什么】一句话，说清这节课学完能干什么。
【现在就做这一件】一个动作，必须含具体对象：哪个文件/哪条命令/哪段代码/在哪个输入框写什么。
【怎么算做对了】可观察的判据：输出长什么样 / 报错消失 / 能解释一句为什么。
【卡住了点这里】一句提示，指向「我卡住了」按钮。
```
其余讲解一律**放在动作之后**，最多 3 段，且每段不超过 5 行。

### 2.2 一次只推进一步
- 助教每次回复只允许包含**一个**待办动作；用户完成后才给下一步。
- 新增「我卡住了」按钮：点了之后助教给「最小可行提示」（一句），不给完整答案；连续点两次才给完整解答。

### 2.3 检查题改判定式
- 不再问「请解释 X 的原理」，改成「做完上面那一步，把你的输出贴上来」或「运行它，把报错贴上来」。
- 判定标准写死：能做出来=通过；做不出来=给下一步最小提示。

## 三、副本（dungeon）改造：先第一步，后地图

现状问题：一进副本就是阶段条、词条、目标，用户不知道从哪个动作开始。

要求：
1. 进副本第一屏只显示：**一句话任务 + 第一步动作 + 「开始」按钮**。阶段条、奖励、词条全部折叠。
2. 每完成一步，才展开下一步；阶段进度用一行小字，不占主位。
3. 副本内也复用「我卡住了」机制。
4. 副本结束页只留：**做出来的东西 + 一条可复制的简历条目**（复用 UserEvidence）。

---

## 四、验收

- 打开任意一节课，助教开场必须包含那四段，且「现在就做这一件」里能找到具体文件/命令。
- 进入副本，第一屏可点元素 ≤ 4，且有一个明确的「开始」。
- 「我卡住了」点击后，第一次只给一句提示。
- 数据清理：首页干净、无残留纪念卡。
- 每项一个 commit + docs/ui-review 截图。
