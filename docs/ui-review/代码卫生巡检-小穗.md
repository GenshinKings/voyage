# 代码卫生巡检（小穗，2026-10-27 22:12）

趁着没人说话，我把仓库过了一遍静态检查。三条实证结论。

## 1. 13 个 Go 文件过不了 gofmt（原因是 CRLF）
`gofmt -l .` 报了 13 个文件：
```
cmd/outpost2/main.go, internal/ability/elo.go, internal/evidence/ledger.go,
internal/graduation/graduation.go, internal/iterate/iterate.go,
internal/kb/{fingerprint,kb,kb_test,license}.go, internal/llm/llm.go,
internal/sandbox/sandbox.go, internal/scheduler/scheduler.go, internal/server/server.go
```
抽查 `internal/llm/llm.go`：**377 个 CRLF**，gofmt 要 LF，所以每个都显示「全文重写」。

不是代码写错，是行尾被 Windows 编辑成了 CRLF。

修法（两步）：
1. 加 `.gitattributes`：
```
* text=auto
*.go text eol=lf
*.md text eol=lf
```
2. `gofmt -w ./cmd ./internal ./fsrs` 之后重新提交一次（纯格式，单独 commit）。

## 2. CI 的 Go 版本和 go.mod 不一致
- `.github/workflows/ci.yml` 写的是 `go-version: '1.24'`
- `go.mod` 要求 `go 1.26.4`

现在靠 Go 的自动 toolchain 下载兜着，所以可能没炸；但这是运气，不是设计。建议改成 `go-version: stable`（或显式 1.26.4）。

顺带确认：CI 的触发分支是 `master`，和仓库实际分支一致，这条没问题。

## 3. CI 少了两步检查
现在只有 `go build` + `go test`。建议加：
```yaml
      - name: vet
        run: go vet ./...
      - name: fmt
        run: test -z "$(gofmt -l ./cmd ./internal ./fsrs)"
```
我本地跑 `go vet ./...` 是**干净的**，加进 CI 不会立刻变红。

## 4. 其它
- `TODO/FIXME/HACK` 全仓只有 1 处，干净。
- `go vet` 无告警。

## 建议顺序
1. `.gitattributes` + gofmt（纯格式 commit）
2. CI 版本改 stable + 加 vet/fmt 两步
3. 再做功能改动
