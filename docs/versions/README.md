# 版本历史（保留每一次转向的理由）

> 目的：让未来的你能看见「当时的我为什么这么想」。
> 代码会变，理由不该丢——不然每次重构都像第一次犯同样的错。

## 怎么读

- 每个大版本一个文件：`YYYY-MM-DD-<版本>-<主题>.md`
- 文件里只写三件事：**当时的判断**、**放弃的做法**、**留下的代价**
- 版本号对应 git tag（见下表），代码可回溯

## 版本表

| 版本 | 时间 | 在解决什么 | 后来怎么评价 |
|---|---|---|---|
| 0.1.x | 2026-10 | 能跑起来：学习页、课程生成、检查题、FSRS 复习 | 骨架对了，但没有「交付」这个结果 |
| 2.0 | 2026-10 | 知识图谱 + 知识地图 + 实战副本 + 心态 | 概念连成网，人还是没交付过东西 |
| **3.0** | 2026-10-31 | **从「学会」转向「交付」**：真实问题 → 做 → 记录卡点 → 按错误出题 | 进行中，见 `2026-10-31-3.0-转向交付.md` |

## 保留规则

1. 每个大版本必须留一份决策记录，**写清放弃了什么**
2. 决策记录不删、不改写历史（改了就在后面追加「修正」段）
3. tag 打在版本号上：`v0.1.0` / `v2.0.0` / `v3.0.0`
4. 计划书（PLAN-*）是「将要做什么」，版本记录是「已经决定了什么」——两者不要混
