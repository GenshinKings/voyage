# 2026-11-01 · 2.0：副本选题改为「目标定方向、学情定内容」，并记录理解薄弱点

这一版没有新功能页面，改的是**副本怎么选**和**助教记得什么**。起因是主人两句判断：

1. 「副本这种的应该是基于学习目标来定副本的大体方向，基于学习的情况和收尾的知识点来定副本选的项目」
2. 「最近 6 个是主要内容，还要有前面的一些内容共同构成这个副本，越早越可能是基础……助教平时看笔记的时候也得记录，xx 知识点的理解有问题，这样构建副本的时候有对症下药，挖坑」

## 改了什么

### 副本选题：从「内容驱动」到「两层输入」

原来 `briefContext` 只给「阅读条目 + 在学科目 + 已收尾知识点」，所以副本实际上是
**读到什么就练什么**——方向由进货决定，跟学习者目标无关。

现在分两层：

| 层 | 输入 | 作用 |
|---|---|---|
| 方向层 | 学习者档案（profile.md，职业/长期目标） | 定副本**类型**：要独立交付 → 端到端小交付；要读懂代码 → 带验收的阅读+改造 |
| 内容层 | 最近 6 个收尾知识点 | 副本**主考内容** |
| 地基层 | 更早的（取靠后 6 个） | 副本要顺带复用，别让基础生锈 |

规则写进给模型的上下文里：**用不上这些知识点就换项目**，不要为了读到的文章硬凑一个副本。

> 为什么地基层重要：越早的知识越可能是基础。地基不稳时只考新东西，人会反复卡在同一个地方。

### 理解薄弱点：记下来，并且能看见、能删

- 新增 `internal/weakpoints`：批注笔记（`/api/inkpal/annotate`）时，每条「理解错了/说不清/漏前提」落盘
- 同一知识点只留最新一条——否则清单会变成没人看的流水账
- 建副本时取最近 6 条，要求「必须在这几处制造判断点，而不是绕开」= 挖坑
- 接口：`GET /api/weakpoints`、`POST`（自己标一条）、`DELETE`（这条不对，删掉）
- 界面：「我的进度」页顶部一张卡

> 为什么必须有界面：系统在用户背后给他人贴标签、却从不告诉他，比不记还糟。
> 而且只能增不能删的清单，最后一定没人看。

## 验证

- `go test ./...` 25 包全绿；`gofmt` 干净
- 真机：加一条薄弱点 → 列表可见 → DELETE 后剩 0 条
- 架构预算拦下两次（新代码里 `_ = json.NewDecoder(...)` 让忽略数 74→76），当场改成判错返回 400

## 已知没做的

- 薄弱点还不会自动过期：很老的病灶应该淡出，而不是一直拿来挖坑
- 副本选题的两层输入目前靠提示词约束，没有硬校验（比如「副本用到的知识点」没有结构化记录）
- 2.0 里「项目通关」的遗留代码还在，等 3.0 稳定后清
