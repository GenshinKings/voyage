# 评审清单（小穗用，逐条打勾）

## 一、先看它有没有回答被问的问题

- [ ] 范围是否等于契约里「要做什么」的三条，没偷偷加东西
- [ ] 是否说了「不做什么」，还是把该砍的又带回来了
- [ ] 有没有把决定权推回给人（「建议你决定」可以，但不能全是这种）

## 二、再看能不能验

- [ ] 每条验收都有可执行的验证方式，不是「应该可以」
- [ ] 声称的测试/构建结果能不能在本地复现（我自己跑一遍）
- [ ] 测试数量、覆盖的说法对得上实际代码

## 三、然后看有没有过度设计

- [ ] 有没有自己造加密、自己造协议、自己造框架（v1 一律不该有）
- [ ] 依赖是不是必要的，能不能用标准库换掉
- [ ] 有没有为「以后可能用到」提前抽象

## 四、最后看它有没有留下记账

- [ ] 提交信息写清做了什么 + 验了什么
- [ ] ARCHIVE 一步有没有做（规则与坑有没有落成文档）
- [ ] 下一轮要用的入口（命令、路径）是否被写下来

## 判词只有三种

1. **收**：五项都过，进 ARCHIVE
2. **打回**：指出第几条第几款，要求重做那一部分，别重写全文
3. **降级**：方向对但做太大，砍到一条最小可验的再交
