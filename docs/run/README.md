# 项目通关（Project Run）

> 「从零带人做出一个又一个有用的开源项目」——这是 voyage 的产品主线。
> 本文是它的设计说明、接口契约与当前状态。改这个模块之前先读这一页。

## 一、为什么是这个方向

目标用户是**「跟过教程、自己琢磨过、但从没把一件事交付出去」的人**。

这类人不缺信息，缺的是三样东西：

1. 一个**从零到发布**的完整路径（不是片段知识）
2. 每一步**能自己验证**的验收标准（不然永远不知道自己算不算会了）
3. 卡住时**只给下一步**的引导（给答案就变成抄）

所以产品的核心不是题库，是**关卡线**：一次只给一关，过不了不解锁下一关。

## 二、关卡线

四档梯度（纵向），每档都走同一串关卡（横向）。

| 档 | 名字 | 「有用」的判据 |
|---|---|---|
| T1 | 单文件小工具 | 解决你自己一个具体的麻烦，三天后还会打开它 |
| T2 | 带存储 | 关掉再开，数据还在 |
| T3 | 接外部接口 | 和真实世界换一次数据 |
| T4 | 有人真的在用 | 有一个人（不是你）用过并抱怨过一句 |

每档的六关：

1. **立骨架** — 能跑起来、能退出的空壳
2. **最小闭环** — 一个输入进、一个结果出（可以先硬编码）
3. **第一条测试** — 让「能跑」变成「跑不坏」
4. **README** — 这是什么 / 怎么装 / 怎么用
5. **发 v0.1** — 有一个可引用的版本
6. **三天后还用吗** — 确认是「有用」而不是「做完了」

T2/T3/T4 在第 3 关和第 4 关之间多插一关（存储 / 外部接口 / 真人使用）。

每一关只有四个字段：

```go
type Stage struct {
    ID     string   // 关卡 id
    Goal   string   // 一句话目标（可观察）
    Check  string   // 一条能跑的验收
    Hint   string   // 卡住时只给下一步，不给答案
    Expect []string // 验收时必须出现的片段（命中任意一个即算过；空=需人工/模型判）
}
```

## 三、接口契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/run/templates` | 四档模板列表（含步数） |
| POST | `/api/run/start` | `{"templateId":"t1-fix-my-annoyance"}`，**只返回当前一关** |
| POST | `/api/run/submit` | `{"output":"..."}`，过关才解锁；不过关给 `reason` + `hint` |
| GET | `/api/run/state` | 当前关 / 进度 / 是否完成 |

设计取舍：`start` 故意不返回后续关卡。教学里最贵的不是信息是注意力——一次给全部，人就开始浏览而不是动手。

## 四、代码位置

- `internal/run/run.go` — 状态机：`Start` / `CurrentStage` / `Submit` / `Progress` / `Deliverable`
- `internal/run/templates.go` — 四档模板与关卡线
- `internal/server/handlers_run.go` — 四个接口
- `Server.RunState` — 随 `state.json` 落盘，重启不丢

## 五、当前状态与已知缺口

已完成：

- 四档模板 + 六关闭环 + 门禁判定
- 四个接口 + 状态落盘
- 测试：`internal/run`（模板完整性、门禁、交付证明、空模板拒绝）、`internal/server`（四个接口跑通一次完整流程）

未完成（按优先级）：

1. **前端**：目前只有接口，界面上还看不到这条线
2. **模型判定**：`Expect` 为空的关卡（立骨架/最小闭环/README）现在只做非空校验，需要接模型或人判
3. **项目来源**：现在只能用内置模板；应该支持「用你自己的麻烦」自定义一个

已完成（2026-10-30）：助教对话链路已接入 `r.Context()`；教学指标（独立通过率 /
错误类型分布 / 退档回升率）已落盘并可从 `/api/stats` 取。

## 六、怎么验证

```bash
go build ./...
go test ./...          # 含 internal/arch 的三条架构规矩
gofmt -l ./cmd ./internal ./fsrs
go vet ./...
```

CI（`.github/workflows/ci.yml`）会跑 build / vet / gofmt / test / 命名检查，所以架构测试自动生效。
