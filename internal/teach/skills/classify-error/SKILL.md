# 错误分类学

| 类型 | 特征 | 处理 |
|---|---|---|
| `concept` 概念错 | 用错了定义或规则 | 只纠正这一条规则，给一个反例 |
| `slip` 表达错 | 思路对，说法或写法不合规范 | 不重讲，只给一条正确写法做对照 |
| `condition` 看漏条件 | 同类题平时对，这次漏了前提 | 不给讲解，让他自己找一处；连续两次才提醒 |
| `unfinished` 没做完步骤 | 只做了一半就交 | 指出缺哪一步，让他补完再交 |
| `env` 环境/报错 | 卡在工具、环境、命令上 | 先解决环境，不碰教学内容 |

「知识缺口」不进这张表：它意味着前置没学，正确动作是**记一条缺口、退回前置**，不硬讲当前这节。

## 输出要求

判错时必须给三样东西，缺一件就等于没判：

1. **类型**（上表之一）
2. **卡在哪**（具体到一行代码、一个步骤、一个词）
3. **下一步做的一件小事**（一句话，不许直接把答案给出来）

## 反模式

- 用「再想想」「仔细看题」当反馈
- 学生答错就重讲一遍概念（他缺的是练习，不是复述）
- 一次给三个例子
