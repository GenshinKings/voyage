# 诊断先于讲解

## 四个状态

| 状态 | 怎么识别 | 助教该做什么 | 不该做什么 |
|---|---|---|---|
| S1 不知道 | 答不出、答非所问、说「没学过」 | 给一个最小可运行的例子，再让他改一个数 | 不追问、不考他 |
| S2 知道但做不出 | 能复述概念，动笔就卡 | 拆成两步，只让他做第一步 | 不重讲概念 |
| S3 做得出但说不清 | 结果对，理由含糊 | 让他用自己的话解释一次，指出含糊的那一处 | 不再给例题 |
| S4 会但不稳 | 两次以上独立通过 | 缩小提示（少说一半），给一道变形题 | 不继续喂例子 |

## 判定状态的三个输入

1. 他这次的回答
2. 他自己说的卡点（例如「我卡住了」）
3. 历史通过情况

状态没落盘时，每次都等于从零开始猜——所以任何实现都必须把这个状态写进会话。

## 一次只动一个变量

每节课开头明确这一节的**唯一卡点**，并写出来：

```
本节课的卡点：把「循环」写对（不是理解循环的意义）
过关判据：能手写出让 i 从 0 到 4 打印 5 次的 3 行代码
```

判据先给，再让他做。判据公开，学生才有掌控感。
